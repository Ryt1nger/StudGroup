# Путь к штатному обходу ЛК и СДО РАНХиГС

**Состояние на 10.11.2026.** YDB Serverless `studgroup-credentials-pilot` в `ru-central1` работает с пределами 1 RU/с и 1 ГБ. Сервисный аккаунт имеет `ydb.editor` только на этой базе. Ключ и Document API endpoint сохранены в настройках Render backend без нового деплоя. Таблица реквизитов в YDB ещё не создана. В рабочей Supabase сейчас нет сохранённых логинов и паролей СДО/ЛК; установленная версия backend всё ещё содержит старый путь хранения. Три секрета YDB перенесены в GitHub Actions; остальные секреты worker ещё не настроены. Локально добавлен адаптер YDB и подключён к форме, отзыву согласия и worker, но код ещё не выпущен. Один аккаунт БИ 1.2 проверял чтение расписания, но не доказывает правильность данных другой подгруппы. По временному решению владельца 71 занятие ноября из этого обхода записано как общее расписание БИ 1.2 вместе с 10 предметами; 41 прежняя запись ссылки сохранена, 16 занятий имеют ссылку на встречу или страницу курса. За пределами ноября подтверждённого расписания сейчас нет. Автоматический сбор и показ личных результатов выключены.

## 1. Разделить хранение реквизитов

1. Создать таблицу YDB с непрозрачным идентификатором записи, логином, зашифрованным паролем, версией ключа и временем изменения. В Supabase оставить только указатель и технический статус; не копировать туда логин и пароль.
   Адаптер с подтверждаемыми операциями, подключение формы и worker, а также миграция 0060 для указателя подготовлены локально; миграция 0060 применена к рабочей Supabase, таблица YDB ещё не создана. Бесплатный Render не даёт запускать разовые задания, поэтому добавлен ручной GitHub Actions запуск создания таблицы; необходимые три секрета YDB уже сохранены в GitHub.
2. Добавить backend-адаптер YDB с таймаутами и явными ошибками. Сохранение считается успешным только после подтверждённой записи. Обе формы — первая регистрация и отдельная страница СДО/ЛК — используют один путь и отдельное согласие.
3. При отзыве согласия подтвердить удаление в YDB до ответа `credentials_deleted=true`; если YDB недоступна, показать ошибку и безопасно повторить удаление. Worker перечитывает согласие непосредственно перед входом.
4. Перевести worker на YDB и убрать рабочий fallback к полям пароля в Supabase. Проверить, есть ли старые записи, затем мигрировать или удалить их проверяемо.
5. Отдельно описать размещение остальных персональных данных в US West: профиль, Telegram ID, членство, подгруппа, личный снимок, резервные копии. Перенос только пароля не закрывает этот вопрос.

**Приёмка:** тесты записи, замены, повторного чтения, отзыва, ошибок обеих баз; пароль отсутствует в ответах API, SQL основной базы и логах; сбой не выдаёт ложный успех.

## 2. Проверить и сохранить расписание

1. На аккаунте владельца открыть именно «Моё расписание» ЛК, сверить код группы, карточки месяца и недель, даты, повторы и признаки подгрупп. Неполную или ошибочную страницу не публиковать.
2. Только для пар с отметкой «СДО» открыть переход из расписания, прочитать страницу курса и пометить ссылку как подтверждённую видеовстречу, только страницу курса, неоднозначную, ещё не опубликованную или ошибку. Адрес курса не называть ссылкой на видеовстречу.
3. Сохранить подтверждённые личные недели и месячный резервный снимок, прочитать обратно через API. Из фактически извлечённых занятий создать предметы с нормализацией названий и защитой от явных дублей. Синтетические фикстуры не импортировать.
4. Проверить отображение в кабинете владельца. Для другой подгруппы оставить статус «не проверено» до появления её аккаунта или достоверного источника.

**Приёмка:** месяц совпадает с недельными карточками; занятия, предметы и корректно помеченные ссылки видны в приложении; чужая подгруппа не показана как своя.

## 3. Запустить справедливую очередь

1. В заданиях хранить только идентификаторы, состояние и коды ошибок. Чередовать группы; в первых кругах выбирать представителей разных подтверждённых подгрупп. Не считать неизвестную подгруппу покрытой.
2. Работать одним браузером с паузой. Новые аккаунты идут перед повторными; успешно обработанный аккаунт возвращается не раньше 24 часов. Ошибки и зависшие задания повторяются ограниченно, последний подтверждённый снимок сохраняется.
3. Проверить расписание хоста. GitHub Actions запланирован на 13 и 43 минуту каждого часа, но запускается только при `RANEPA_CRAWL_PILOT_ENABLED=true`; смена ограничена 24 минутами и паузой 20 секундами. GitHub не гарантирует точный старт. Не запускать второй конкурирующий worker.
4. Передать worker секреты Supabase, YDB и шифрования через защищённые настройки. Запускать только при действующем согласии и хотя бы одной учётной записи. Измерить время, память и расход YDB на реальном аккаунте, прежде чем расширять охват.

**Приёмка:** тесты порядка групп и подгрупп, повторов, истёкшей сессии, ошибок входа, CAPTCHA, недоступности ЛК/СДО и перезапуска; данные групп изолированы.

## 4. Выпуск и откат

1. Зафиксировать версии, флаги и резервную копию; выполнить миграции и полный CI при выключенном обходе.
2. Включить сначала только владельца БИ 1.2: отдельное согласие, запись в YDB, реальный вход, проверенный снимок и показ в Telegram/Mini App. Один аккаунт не доказывает покрытие второй подгруппы.
3. Затем добавлять представителей других групп и подгрупп и остальных добровольно подключившихся студентов. Следить за возрастом снимков, задержкой очереди, кодами ошибок без секретов и расходом YDB.
4. При проблеме выключить обход и показ личных снимков, оставить последний подтверждённый результат и вернуть прошлую версию кода. Схемы с согласиями и снимками не откатывать удалением данных.

**Окончательный допуск:** утвердить актуальные документы оператора, проверить размещение всех затронутых персональных данных и допустимость автоматического доступа по правилам РАНХиГС. Значение флага не заменяет эту проверку.
