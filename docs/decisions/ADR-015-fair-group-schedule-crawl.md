# ADR-015: Справедливый обход расписания по группам и подгруппам

Дата: 2026-11-06. Статус: реализовано за флагами; production-включение отдельно.

## Контекст

Расписание и ссылки на дистант зависят от студента, учебной группы и
подгруппы. Последовательный обход всех студентов одной академической группы
задержал бы получение данных другими группами. Долгий браузерный обход нельзя
выполнять внутри сервера бота.

## Решение

- Фоновый worker получает ограниченное число задач из долговечной очереди.
  Время полного недельного прохода не ограничивается одним часом.
- Логин и пароль подключаются студентом в профиле, хранятся зашифрованными
  и могут быть удалены. После вступления в группу с кодом РАНХиГС бот
  предлагает открыть форму приложения. Подключение пока не обязательно для
  вступления; секреты не попадают в
  групповые данные, логи и репозиторий.
- Очередь чередует академические группы. В первых кругах предпочтение имеют
  разные подтверждённые подгруппы внутри каждой группы; при неудаче берётся
  следующий представитель той же подгруппы.
- Успешные результаты сохраняются после каждого аккаунта. Задачи имеют
  состояние и могут безопасно повторяться после сбоя или перезапуска.
- Каждое чтение и запись строго привязаны к академической группе; подгрупповое
  занятие доступно только подтверждённой подгруппе. Неизвестное покрытие
  явно обозначается как неполное.
- Месячное «Моё расписание» ЛК служит резервным снимком. Ссылки ищутся в
  СДО только для занятий с отметкой «СДО»; неоднозначность не разрешается
  догадкой. Подробные правила — в
  [архитектуре расписания](../architecture/ranepa-schedule-sync.md).

## Следствия

Личный API читает последний успешный снимок, пока worker обновляет данные.
Выдача этого снимка через Telegram-бота ещё не подключена. Нужны измерения
времени и памяти реального обхода перед выбором параллелизма. Частичный охват
студентов не означает покрытия всех подгрупп. Автоматическая запись в
production пока не включена.
