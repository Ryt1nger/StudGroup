# ADR-019 — Сохранение расписания независимо от ссылок СДО

Статус: предложено, P0-1 / P0-2, 2026-11-16.

## Контекст

Снимок СДО может содержать меньше занятий, чем опубликованный
редакторский календарь. Отсутствие пары в одном источнике не является
подтверждённой отменой. При этом результат поиска Moodle-ссылки имеет
собственные частичные состояния и ошибки, не определяющие валидность недели.

## Решение

- Для отображения объединять отдельные occurrence по дате, времени,
  предмету и совместимому преподавателю, а не заменять день целиком.
- Редакторскую запись и её ID сохранять. Если совпадение неоднозначно,
  не скрывать ни одну опубликованную пару, а выдавать безопасный счётчик конфликта.
- Проверенное поле `cancelled` показывать как отмену только совпавшего
  занятия; отсутствие строки никогда не является tombstone.
- Сначала сохранять валидную неделю и фиксировать транзакцию. Затем
  отдельно искать прямые ссылки и курсы и независимо делать транзакционный
  link-only update. При ошибке enrichment старый проверенный снимок остаётся.
- Состояния matcher централизованы в `ranepa_link_states.LinkState`.
  Строковые значения API сохраняются для старых клиентов.
- `course_url` не становится `online_url`; отдельное UI-действие
  «Открыть курс СДО» не является кнопкой подключения.
- Ответ RuCaptcha/движение ползунка не является проверкой расписания.
  Успех зависит от повторного чтения источника и валидации группы.

## Приёмка и регрессия

- [x] P0-1: частичный день сохраняет все опубликованные пары.
- [x] P0-1: отмена меняет только идентичную occurrence.
- [x] P0-2: все matcher states принимаются реальным writer.
- [x] P0-2: ошибочный enrichment не откатывает schedule commit.
- [x] P0-2: интеграция worker + SQLAlchemy без mock remember_personal.
- [ ] CI: автоматические тесты должны пройти перед merge.

Совместимость: без SQL-миграции и без изменения обязательных полей
существующих ответов `/v1/schedule` и `/v1/ranepa-schedule`. Добавленное
в JSON строки снимка поле `links_checked_at` игнорируется старыми читателями.
Никакого массового переноса старых снимков или live deploy без решения владельца.
