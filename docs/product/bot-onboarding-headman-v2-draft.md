# StudGroup — Telegram-бот: путь старосты v2 (проект на согласование)

**Статус:** проект интерфейса и сценария, не утверждён.  
**Ветка:** `feature/bot-onboarding-buttons-v2`.  
**Область:** исключительно личная переписка с ботом; публичные команды только `/start` и `/admin` (админку прорабатываем отдельно).  
**Основа:** схема пользователя от 05.11.2026. Никаких изменений production-данных и рассылок в рамках этого документа.

## Общие правила

1. Каждый шаг — одно редактируемое сообщение бота с inline-кнопками. Произвольный текст нужен только для названий, кодов и иных вводимых значений. Старые и истёкшие кнопки не должны выполнять действия.
2. При `/start` сервер проверяет реальные права и прогресс, а не предлагает выбирать роль второй раз. Активный староста с завершённой настройкой сразу видит кабинет; незавершённая настройка — продолжение.
3. Навигация через «Назад», «Отмена», «Главное меню» как кнопки (без требований вводить другие команды).
4. Все изменения роли и приглашений проверяются на сервере, идемпотентны и привязаны к конкретному Telegram ID и chat ID. Telegram-права и права бота проверяются повторно перед окончательным подключением.
5. Ничего не писать в общем чате; никаких платных AI-вызовов на онбординге.
6. Кнопка «Открыть приложение» допустима в кабинете, но весь онбординг выполняется через бот.

## Условие показа выбора подгрупп студенту

- Разделение на подгруппы при первоначальной настройке старостой **необязательно**. Если староста выбирает «Нет» или не настраивает ни одного разделённого предмета, **студенту вообще не показывается экран выбора подгруппы**; сразу после подтверждения вступления он видит «Готово» и главное меню.
- Если староста настроил один или несколько предметов с подгруппами, после вступления студент выбирает подгруппу **только по этим предметам**. Если выбор по одному из них не завершён, повторный `/start` предлагает завершить соответствующий выбор.
- Если староста добавил разделение позднее, запрос выбора появляется только у тех студентов, у которых нет выбора по новому разделённому предмету. Не следует возвращать к онбордингу остальных или задавать вопросы про несуществующие разделения.
- Наличие предмета в расписании само по себе не означает разделение на подгруппы. Основание для шага — только сохранённая конфигурация разделения от старосты.

## Возврат и восстановление

- `/start` во время онбординга показывает актуальный шаг, а не сбрасывает уже подтверждённое подключение. Роль нельзя назначить просто по изменению шага.
- После H4 повторный запрос должен приводить к той же группе без повторного создания membership.
- Если H5/H6/H7/H8–H11 прерваны, следующим `/start` предлагается «Продолжить настройку» и «Кабинет старосты».
- Из H11 можно вернуться к предыдущему вводу и исправить его; перед H11s нет живых изменений общей конфигурации.
- Если староста пропустил подгруппы, их всегда можно настроить из кабинета кнопками.
- Если бот исключён из чата или потерял нужные права, не показывать неверный статус «всё работает». В кабинете появляется действие «Исправить подключение».
- Если группа уже привязана к другому старосте, предложить безопасное объяснение и обращение к действующему старосте/поддержке; не перехватывать её.

## Решения, которые нужно явно закрепить до реализации

1. **Смысл промокода.** В текущем коде нет полноценной модели промокодов. Нельзя принимать произвольную строку как якобы действительный промокод. В интерфейсе шаг есть по схеме, проверку нужно разработать отдельно вместе с моделью действия кода (скидка, пилотный доступ и т.п.).
2. **Вид приглашения.** В старом коде ссылка одноразовая и истекает через 24 часа. Для показанного пути старосты логичнее одна управляемая ссылка группы, доступная многим проверенным Telegram-участникам, с возможностью отзыва/перевыпуска. Это предложение, а не утверждённая замена.
3. **Как подтверждается староста.** Рекомендуется положительная проверка Telegram-администратора и явное нажатие «Да, подключить», без автоматического назначения добавившего при неизвестном статусе.
4. **Названия/признаки подгрупп.** В онбординге — бесплатный детерминированный ввод. Не вызывать AI только ради названия.
5. **Минимальные права бота.** Утвердить точный набор разрешений исходя из Telegram API и существующего приёма сообщений.
6. **Готовность группы.** Отдельно различать «бот добавлен», «права проверены», «роль старосты подтверждена», «онбординг завершён».

## Критерии приёмки этапа

- Новый староста полностью проходит весь путь из схемы без других Telegram-команд.
- Повторный `/start` в любой точке не теряет прогресс и не дублирует группу/приглашения.
- Работают кнопки «Назад» и «Отмена» и показано конкретное сообщение при ошибке.
- Сохранение подгрупп выполняется один раз после явного подтверждения.
- Уже подключённый староста сразу попадает в кабинет.
- Студенты ничего не получают и не теряют в ходе тестирования, существующие карточки и расписание не меняются.
- Нет вызовов платного AI.
