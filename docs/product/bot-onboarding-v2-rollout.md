# Telegram-бот StudGroup v2 — выпуск и ручная проверка

**Статус:** код реализован в feature-ветке, production не затрагивать до ручной приёмки.  
**Рабочая ветка:** `feature/bot-onboarding-buttons-v2`.  
**PR:** #69 (draft).  
**Цель:** кнопочный онбординг старосты и студента, постоянные меню и безопасные системные уведомления.

## Предварительные условия

- [ ] Убедиться, что последний **полный** backend CI для head SHA зелёный: Ruff, миграции, pytest.
- [ ] Подготовить отдельный **тестовый Telegram-чат**, не использовать рабочую БИ 1.2 для проверки регистрации.
- [ ] Убедиться, что бот имеет нужные права Telegram, и у тестового старосты есть права администратора.
- [ ] Перед выпуском проверить состояние настроек AI: онбординг не вызывает платный AI; после подтверждения новой группы штатная обработка сообщений может иметь стоимость. Согласовать пилотный лимит до настоящего включения новых групп.
- [ ] Сохранить резервную копию БД перед применением миграций.

## Миграции и совместимость

- `0050_reusable_group_invitations.py`: флаг `reusable` по умолчанию `false`; ранее выпущенные одноразовые коды сохраняют старое поведение.
- `0051_academic_group_code.py`: `groups.academic_group_code` допускает `NULL`; `academic_group_code_required` по умолчанию `false`. Для уже подключённой БИ 1.2 код не обязателен и доступ сохраняется.
- Для **нового** обнаруженного чата `pilot_authorized=false`: до явного подтверждения старосты сообщения не попадают в обработку. После подтверждения роли `pilot_authorized=true`; перед выдачей приглашений для новой группы официальный ID обязателен.
- Настройки уведомлений используют прежний `user_profiles.settings` и не требуют самостоятельной миграции.

## Ручной E2E: староста

1. Отправить `/start` в личку; проверить ровно шесть стартовых кнопок и работоспособность «Назад».
2. «Подключить группу» → «Я староста» → «Нет промокода»; альтернативно проверить ввод промокода: до запуска партнёрской механики он **не применяется**.
3. Добавить бота в новый тестовый Telegram-чат. Проверить в БД `pilot_authorized=false` и отсутствие `raw_messages` от последующих сообщений до явного подтверждения.
4. Нажать «Проверить подключение»; без admin-прав пользователя или бота назначение старосты должно быть заблокировано.
5. С подтверждёнными Telegram-admin правами выбрать найденный чат и нажать «Да, подключить». Старостой становится только нажавший.
6. Ввести официальный ID РАНХиГС либо подтвердить распознанный из названия чата. Проверить, что код сохранён отдельно от Telegram-названия и что без него для нового чата нельзя создать приглашение.
7. Создать общую ссылку приглашения, отправить двум участникам чата. Убедиться, что оба могут активировать доступ, а отсутствующий в чате — нет.
8. «Далее: подгруппы» → «Нет»: кабинет открывается; ни один студент не получает вопрос о подгруппах. Повторить на другом тестовом наборе данных с разделением: выбор задаётся **только** по настроенным предметам.
9. Заново выполнить `/start` после каждого этапа незавершённой настройки: подтверждённый прогресс не теряется.
10. При замене групповой ссылки старая перестаёт работать, новая проходит проверку текущего Telegram-членства.

## Ручной E2E: студент

1. По новой ссылке получить доступ только после Telegram-проверки; попытка вступить в ещё одну активную группу должна быть отклонена.
2. При отсутствии разделения студент видит «Готово» → главное меню **без шага подгрупп**.
3. При существующем разделении студент выбирает нужные подгруппы, может прерваться и продолжить выбор после `/start`.
4. Проверить меню «Уведомления» и сохранение настроек; «Проверить подключение» не меняет доступ при отказе Telegram API.
5. Проверить «О нас», «Помощь», «Поддержка», «Партнёрка», «Тарифы»: возврат кнопками, никаких выдуманных тарифов/партнёрских выплат.

## Уведомления и бюджет

- [ ] Для нового разделённого предмета отправляется максимум одно системное сообщение на нужного студента; при отключённых уведомлениях — ни одного.
- [ ] Тихие часы сдвигают отправку на допустимое локальное время. Если к моменту доставки студент уже выбрал подгруппу или отключил уведомления, очередь отменяет сообщение.
- [ ] Бот остаётся молчаливым в общем чате; тестовый онбординг не делает AI-запросов.
- [ ] Инструкция владельца по управлению стоимостью AI проверена отдельно; **не** считать доступное членство группы гарантией нулевых AI-расходов при последующих учебных сообщениях.

## Порядок выпуска

1. Дождаться зелёного CI и завершить ручную E2E-приёмку в отдельном чате.
2. Применить миграции к staging, повторить сценарии, проверить права и логи.
3. До production проверить лимит AI, резервную копию, совместимость действующей БИ 1.2.
4. Слить PR в `main` только после приёмки; выкатить backend через существующий deployment pipeline.
5. Синхронизацию команд Telegram (только `/start` для студентов, `/admin` дополнительно владельцу) выполнить **после** backend deployment явным операторским действием `uv run python -m studgroup.telegram_commands`; не запускать её на каждом старте.
6. После выката проверить `/start` старого участника БИ 1.2, существующие карточки и историю, а затем нового тестового студента.
7. Если обнаружены ошибки: прекратить новые подключения, откатить приложение на предыдущий deployment; **не удалять новые столбцы до оценки данных**. Отдельно оценивать совместимость миграций при откате.

## Ограничения версии

- Промокод — интерфейсный необязательный шаг; списания, скидки и партнёрские выплаты пока не реализованы.
- Подготовлены настройки академических уведомлений в профиле; наличие переключателей не означает, что все соответствующие рассылки отправляются.
- `/admin` проектируется отдельно. Старые внутренние маршруты команд временно оставлены для совместимости, но в публичном меню команд Telegram не публикуются.
