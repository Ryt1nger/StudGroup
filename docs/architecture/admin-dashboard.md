# Админский дашборд

Адрес страницы: `/admin/` на том же домене, что и backend API. В личном чате с ботом
слово «админ» (регистр не важен) показывает одну кнопку «Открыть админку», если задан
`ADMIN_PAGE_URL` (полный HTTPS-адрес этой страницы). Команда `/admin` сохраняет
прежний экран управления группами и также показывает кнопку дашборда. Telegram
открывает WebApp после нажатия кнопки пользователем. Страница работает как Telegram
WebApp: `initData`
проверяется существующим `/v1/session/bootstrap`, затем read-only запросы идут в
`GET /v1/admin/dashboard`. Токен хранится только в памяти вкладки. Доступ к данным
разрешён только `BOT_ADMIN_USER_ID`; членство в группе и роль старосты сами по себе
не дают доступа. Страница не выводит исходные сообщения, личные данные или ответы AI.

Данные запрашиваются при открытии, смене группы, ручном обновлении и раз в минуту,
пока вкладка видима. Каждая выборка выполняется по текущим строкам PostgreSQL; поле
`as_of` показывает время среза. При недоступности API старые значения остаются на
экране, а статус показывает ошибку.

| Блок | Источник и смысл |
| --- | --- |
| Группы и участники | `groups` с `status=active`, `pilot_authorized=true`; активные `memberships` |
| Поток сообщений | `raw_messages.message_date` за последние 7 дней, последнее сообщение и распределение по `processing_state` |
| Публикации | `homework.status=published`, действующие `academic_deadlines`, активные `canonical_academic_items`, опубликованные `group_events` |
| Уточнения | Действующие `academic_deadlines.needs_clarification=true` |
| Очереди | Состояния `ai_jobs`, `shadow_evaluation_runs`, `image_analysis_jobs`; `bot_outbox` общесистемный |
| Расходы | Отдельно суммы `analysis_budget_calls.charged_usd`, незакрытых резервов, `ai_attempts.charged_usd` и `image_analysis_calls.charged_usd`. Журналы могут описывать одни и те же вызовы, поэтому эти суммы нельзя складывать. |
| Режимы | Текущие runtime-флаги, `group_analysis_settings.analysis_mode` и `paid_outcome_hold` |
| Расписание | Текущая версия расписания каждой группы из `groups.schedule_version` |
| Инциденты | Открытые `owner_incident_episodes`, без деталей запросов и личного текста; блок общесистемный |

Фильтр группы применяется только к сущностям с `group_id`; инциденты и Telegram
outbox всегда общесистемные. Метрики имеют разные сроки хранения исходных строк;
нулевое значение означает отсутствие строк в текущей БД, а не доказательство
отсутствия исторической активности.

## Приёмка

- Обычный пользователь получает 403 на API; отсутствующий или истёкший токен — 401.
- Фильтр группы не включает строки другой группы; несуществующая группа — 404.
- Счётчики меняются после изменения строк БД без пересборки интерфейса.
- API и HTML не раскрывают текст сообщений и секреты.
- На слово «админ» кнопка появляется только при заданном `ADMIN_PAGE_URL` в личном
  чате пользователя `BOT_ADMIN_USER_ID`; другим пользователям ссылка не выдаётся.

Новый API аддитивен и не меняет контракты пользовательского фронтенда или его
существующие ответы. Контракт локален для страницы backend; несовместимых изменений нет.

## Центр владельца — детализация (2026-11-08)

Админка `/admin/` обновлена как интерактивная панель без демонстрационных данных.
`GET /v1/admin/analytics?days=7&group_id=...` возвращает актуальные сводки
и дневные ряды из рабочей БД. Допустимые периоды: 1–90 суток. `GET
/v1/admin/details/{kind}?days=7&group_id=...&offset=0&limit=40`
возвращает постраничные записи для модального окна. Оба API требуют
существующую owner-сессию `BOT_ADMIN_USER_ID`; пользовательских маршрутов
WebApp и AI-вызовов они не создают. Ошибки можно раскрыть до кода,
этапа, времени, количества попыток и идентификатора записи без выдачи
текстов Telegram и входных данных модели.

Графики сообщений измеряют **сообщения в чатах**, а не визиты в WebApp.
Авторы сообщений — число уникальных Telegram-отправителей за период.
`web_sessions` не содержит даты создания/открытия, поэтому считать
исторические заходы по этой таблице некорректно. Отдельный сбор событий
посещений и использования функций пока **не подключён**.

`analytics.summary.spent_usd` и график расходов берутся только из
`analysis_budget_calls.charged_usd`. Старые `ai_attempts` и
`image_analysis_calls` потенциально содержат пересекающиеся вызовы,
поэтому их суммы **нельзя добавлять** к основному журналу. Для текущего
месяца используется начало календарного месяца UTC, тогда как фильтр
`days` выбирает последние N календарных дней по UTC, включая текущий. Резервы — отдельно и не считаются
потраченными или доступными деньгами.

У проекта пока **нет надёжного учёта** поступлений на счета компании,
списаний с банков, неоплаченных счетов, платёжного календаря и live-балансов
AI-провайдеров. Поля `finance.company_balance_usd`,
`company_revenue_usd`, `provider_balances`, `subscriptions` возвращают
`null`; интерфейс пишет «Нет подключения», не ноль. Для их реализации
потребуется согласованный источник финансовой истины и подключение
сервисов с реальными полномочиями на чтение.

Время текстового и фото AI берётся из записанных `latency_ms`; это
**не скорость загрузки страниц**. Фронтенд отдельно измеряет round-trip
текущего запроса и показывает время составления среза на сервере.
Исторические p95/p99, CPU/RAM, uptime и распределение HTTP-ошибок Render
не хранятся в базе приложения и не отображаются как вымышленные значения.
Статусы очереди исходящих Telegram и инциденты системные, не
ограничиваются фильтром группы. Telegram outbox не имеет даты
отправления; его состояние отображается за всё время.

При внедрении важно проверить привязку production DATABASE_URL к новой
региональной базе, права owner-сессии, и запустить `test_admin_insights.py`
в CI перед публикацией. Backend в Render не деплоится автоматически,
поскольку у сервиса `autoDeploy=off`. Изменение кода в Git не означает
публикацию на production.

## Панель для владельца: понятные метрики и интерактивные графики

Новая версия читает GET /v1/admin/visuals вместе с /analytics и /details.
Все API read-only и доступны только BOT_ADMIN_USER_ID. Вверху — простые
показатели; технические поля скрыты в раскрываемых подробностях модальных окон.

- Верхние показатели: сообщения, текстовый AI, проходы фото, ошибки,
  расходы AI за месяц и открытые предупреждения. Относительная динамика
  сравнивается с предыдущими N календарными днями; при нулевой базе
  процентный рост намеренно не рассчитывается.
- Активность: сообщения за дни и по часам, число авторов Telegram-чатов.
  Это не посещения WebApp или ежедневные активные пользователи приложения.
- AI: количество прогонов, распределение исходов текста и фото,
  средняя длительность, новые ДЗ, события, уведомления. Один файл фото
  может иметь два прохода. Статус stale — заменённый результат, не сбой.
  Успешный прогон не означает подтверждённую правильность карточки.
- Финансы: суммы основного журнала analysis_budget_calls по дням/типам
  в UTC и отдельные незакрытые резервы. Балансы провайдеров, поступления,
  счета и платежи компании недоступны без отдельного источника.
- Сервер: встроенные p50 (медиана), p95 (95-й процентиль), HTTP 5xx и
  число API-запросов за 15 минут. Максимум 2000 последних вызовов в памяти.
  Не сохраняются IP, пути, токены, тела запросов или идентификаторы.
  После перезапуска история обнуляется. Это не мониторинг uptime/CPU/RAM.
- Ошибки: динамика по дням, частые технические коды с понятными
  объяснениями, защищённые модальные окна с временем и попытками.
- Любой график кликабелен: открывает связанные записи из /details.
  Визуализация — собственный admin_ui/visuals.js без внешнего SDK.

Даты дневной статистики и часы активности подписаны UTC. Не следует
объявлять отсутствие старых записей доказательством отсутствия активности.

## Визуальная панель для владельца (2026-11-08)

Визуальная версия `/admin/` разделена на пять рабочих разделов:
активность, AI, расходы, скорость сервера и ошибки. В ней применяются
линейные/площадные графики, столбцы по дням и часам, диаграммы структуры,
мини-графики с сравнением периодов и список главных проблем. Основной
уровень содержит простые русские названия и объяснение значения;
технические коды скрыты под раскрывающимся разделом карточки в модальном
окне. Каждая доступная метрика имеет детализацию или объяснение
недоступности источника.

Дополнительный owner-only API `GET /v1/admin/visuals?days=N&group_id=UUID`
обслуживает графики из действующих таблиц. Дневные интервалы строятся
по UTC, фильтр N=1 означает текущий календарный день UTC, а сравнение
с предыдущим периодом использует *ту же фактическую длительность*,
чтобы неполный текущий день не искажал динамику. Распределение сообщений
по часам пересчитывается в Europe/Moscow. Показатели Telegram-сообщений
не называются входами или активностью WebApp.

Замеры API записываются только в ограниченный кольцевой буфер текущего
python-процесса (не более 2000 обезличенных событий, окно 15 минут):
коды результатов, время отклика и число запросов по минутам. Никакие
пути, IP, заголовки или идентификаторы не пишутся. Это не серверный uptime
и не история CPU/RAM; при деплое и рестарте буфер начинается заново.

Фото в базе — это *проходы анализа*, а не количество уникальных
фотографий. Состояние `stale` означает устаревший результат, а не
ошибку. Ошибки текстовой, фото- и старой очередей могут относиться к
одной причине и не являются количеством уникальных инцидентов.
Время AI измеряется по записанным `latency_ms`, а не по скорости
открытия Mini App.

Финансовый график текущего месяца рассчитывается только из
`analysis_budget_calls`, не суммируется с legacy-журналами.
Балансы провайдеров, реальные оплаты сервисов и банковские счета
пока не подключены и выводятся как `Нет данных`.
Доступ защищён существующей проверкой `BOT_ADMIN_USER_ID`.
Фронтенд рисует SVG локально, без сторонних CDN и платных аналитических
сервисов. Все графики и модальные окна являются read-only.
